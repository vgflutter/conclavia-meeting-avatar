# PoC audit — 10 September 2026

## Result and scope

The full functional regression run passed **140 tests**. The 33 new trigger scenarios also passed three consecutive repetitions (**99 additional executions**). A subsequent visual filter correction passed **12 targeted rendering, streaming and lip-sync tests**, including a new visual regression case. ESLint, TypeScript and a separate-directory production build passed. This is a local application and provider integration audit, **not a completed receiver-side Teams acceptance test**.

The app reported no active meeting when checked. No real Teams participants were created, admitted or removed. Existing meeting history and credentials were preserved. Real-service scripts created uniquely named, `autoJoin: false` fixtures and removed those records afterward.

## Reproduced defects and fixes

The original 107-test suite passed, but the new 32-case audit initially exposed failures in 25 cases. These were several underlying defects, not 25 unrelated bugs:

- **Wrong addressee / incidental mentions:** “Ciao Marco, mi senti?” and “Ho chiesto a Riccardo di controllare il budget” activated Riccardo. Wake-word matching now requires direct address, allowing greetings and short courtesy prefixes. Reported speech and quotations do not activate it. The existing exact, nameless “Ciao, mi senti?” audio check remains supported.
- **Recall versus storage:** “Riccardo, ricordami il budget” stored the remainder of the question. `ricorda` / `remember` now require a complete word; `ricordami` stays a question and does not mutate memory.
- **Dynamic names:** accented and multiword names are tested alongside Riccardo and Nora. Lost double letters such as “Ricardo” remain supported without guessing unrelated captions such as “Charlie cardo”.
- **Unsafe arithmetic correction:** the integer shortcut matched inside decimals, negations, quotations and hypothetical statements. It now accepts only a complete affirmative integer claim and checks safe-integer bounds. Other claims require contextual evaluation; they are not automatically declared false.
- **Accidental agenda completion:** negative, uncertain and interrogative phrases no longer close items. An unrelated title cannot close the only remaining item. Completion requires an unambiguous title match or an explicit current-item reference; ambiguous requests ask for clarification.
- **Participant mistaken for bot echo:** a human named “Riccardo Rossi” was suppressed by prefix matching. Echo suppression now compares the exact configured name, removing known Guest/Unverified display suffixes first.
- **Feature switches:** disabled question answering, voice memory capture and on-request summaries now suppress their corresponding voice triggers. This added the 33rd audit scenario.
- **Rectangular noise around the face:** inspecting the real public-browser screenshot revealed that an SVG turbulence filter painted beyond the head. Removed that decorative filter while preserving the head path, gradients and animation. The new browser regression checks both the absence of turbulence and the head/clip geometry match. This fixes the source image artifact, not Teams bitrate or negotiated resolution.

Split wake-word captions require the same speaker within eight seconds. Permission rejection, proposal expiry, disabled proactive interventions and duplicate webhook delivery are covered by regression tests.

Replace “Riccardo” with the meeting's configured invocation name.

| Feature | Example / trigger | Verified behavior |
| --- | --- | --- |

| Store memory | “Riccardo, ricorda che il budget è approvato” | Persisted once; duplicate fact does not create another memory entry |

| Summary | “Riccardo, riepiloga” / finalization | Summary preserves tested amount, date and named responsibility; history remains available |
| Agenda | “Riccardo, scaletta” / agenda command with “Budget completato” | Required next item, explicit completion, no completion on negation or ambiguity |
| Explicit verification | “Riccardo, verifica la data” | Verification command parsed; contextual evidence required |
| Proactive correction | Clear arithmetic error or conflict with stored budget | Pending proposal; no correction response queued before permission |
| Relevant contribution | Current topic matches a reliable stored responsibility | Real AI proposes the useful fact and waits |
| Grant / decline | “Riccardo, vai pure” / “Riccardo, non ora” | Grant releases the prepared text without another model call; decline clears it |
| Expiry / disabled policy | Expired proposal / proactive policy off | No stale proposal or unsolicited arithmetic response |
| Debug | Optional live transcript panel | Live updates, reconnect, bounded history, disabled/hidden-tab cleanup, mobile layout |
| Entry / exit / retry | Provider lifecycle fixtures | Single participant claim, uncertain creation, persisted deadlines, exit confirmation, stale callbacks and restart reconciliation |

| Voice / lip sync | Streaming and local-engine browser tests | Non-silent audio, completed playback, phoneme/audio-clock animation, stop/replay and queue behavior |

## Real-service results

### Answers and cross-meeting memory

`npm run test:live` passed nine command checks against the configured running app. It verified an owner and delivery date from previous-meeting memory, English answers despite Italian notes, an unknown fact, agenda completion, and a summary containing 48,000 euro, 27 November and Marco Bianchi.

Observed HTTP response times: owner **2,318 ms**, delivery date **1,373 ms**, English owner answer **746 ms**, unknown fact **715 ms**, summary **1,337 ms**. Memory and agenda operations took **19–23 ms** after initial route loading. These measure response text, not audible Teams latency.

### Proactive interventions

`node scripts/verify-live-interventions.mjs` passed both scenarios with **real AI and synthetic Attendee callbacks**, not a real Teams participant:

| Scenario | Proposal ready | Permission to persisted response |
| --- | --- | --- |
| Stored budget 48,000 versus spoken 99,000 | 2,852 ms | 50 ms |
| Remind the meeting of the assigned test owner | 3,057 ms | 33 ms |

Both proposals remained pending until the configured name received permission. Their answers contained the verified budget / Marco Bianchi respectively. Fixtures were ended through their synthetic lifecycle and removed. This opt-in script incurs model usage, including finalization; it never calls bot creation or admission APIs.

### Streaming voice

`node scripts/verify-streaming-voice.mjs --compare` made three real Inworld requests with “Ciao, sono Riccardo. Ti sento, dimmi pure.”:

| Model / run | First PCM | First non-silent browser playback |
| --- | --- | --- |
| Flash, first | 778 ms | 1.15 s |
| Flash, second | 307 ms | 0.36 s |
| TTS-2 | 394 ms | 0.48 s |

All streams returned HTTP 200, completed, contained 40 phoneme entries and non-silent audio, and changed mouth shape during playback. No duplicated voice requests were observed. Local-engine fallback playback also passed on GPU and CPU in both full regression runs. CPU synthesis remains slower and is not the preferred real-time path.

The bounded context strategy remains in place: deterministic commands bypass the model; contextual answers retrieve at most 14 memory entries (4,000 characters) and the latest 36 transcript segments (7,000 characters). Output caps are 120 tokens for ordinary answers and 180 for summaries. These are limits on selected sections, not the entire request's token count. Model generation, caption delivery, network transit and meeting playback must still be measured separately.

## Local connectivity recovery

The saved Quick Tunnel hostname no longer resolved. The existing tunnel process was identified as belonging to this repository and forwarding to port 3000. A new tunnel was started, and only `CONCLAVIA_PUBLIC_URL` was changed in the ignored `.env.local`; API keys were not changed.

The public health route returned 200, while `/meetings`, `/api/meetings` and `POST /api/avatar/speech` returned 404. After the hostname changed, avatar HTML/state responded but executable assets returned 403: Next's development origin allowlist still used the old hostname. A server restart is required, not just editing the environment variable. The previous server also stalled during graceful shutdown while retaining its lock; only the identified project processes were terminated before restart. No lock or database files were deleted.

After the restart, the **full public avatar preflight passed**: HTML, voice-ready state and executable assets were reachable. Its temporary, non-joining record was removed. The app and replacement tunnel were left running for the next test.

A separate Chrome run through the public hostname also passed: the avatar was visible, the hydrated page made three successful state reads and there were zero browser JavaScript errors. A local screenshot is retained at `test-results/public-avatar-audit.png` (ignored by Git). This did not create a participant or synthesize speech.

Do not reuse a stale hostname or assume “health 200” proves that video works. The full preflight checks avatar HTML, state and executable JavaScript with the public origin header. Keep the local computer, app and tunnel running; company deployment requires stable HTTPS and an always-on process as explained in the [README](../README.md#production-deployment).

## Remaining acceptance gate

No active admitted Teams session was available during this audit. The following are **still not certified**:

- receiver-side time from the end of a spoken question to first audible answer, including Teams captions and provider transport;
- subjective Italian voice naturalness and lip sync as received through Teams;
- initial and sustained video sharpness / negotiated resolution;
- a real admitted entry–conversation–exit–re-entry cycle with the updated streaming voice;
- unattended company deployment, SSO and meeting admission policy.

The app is substantially better covered and ready for the next controlled acceptance run. A green local regression suite must not be described as completion of that real-meeting acceptance gate.
